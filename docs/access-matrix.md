## 2. Політика доступу до деталей інциденту

Головною захищеною операцією лабораторної роботи №4 обрано `GET /api/incidents/{id}`.

Встановлено такі правила доступу:

- **Анонімний користувач:** доступ заборонено, HTTP `401 Unauthorized`.
- **Reporter (Alice або Bob):** доступ до власного інциденту дозволено, HTTP `200 OK`.
- **Reporter для чужого інциденту:** доступ заборонено, HTTP `404 Not Found`.
- **Analyst (Morgan):** перегляд інцидентів дозволено для виконання аналітичних завдань, HTTP `200 OK`.
- **Administrator:** сама назва ролі не надає автоматичного права переглядати чужі інциденти. Власний ресурс доступний за загальним правилом власника; для чужого без окремого дозволу повертається `404 Not Found`.

Правила визначаються сервером на основі автентифікованого користувача, його ролі та власника конкретного інциденту.

## 3. Обґрунтування політики HTTP-відмов

Для спроби перегляду чужого інциденту обрано політику `404 Not Found`.

Ця політика дозволяє приховати від користувача без належних прав сам факт існування чужого ресурсу.

Для чужого та неіснуючого інцидентів сервер використовує однакову відповідь `404` з повідомленням «Інцидент не знайдено».
