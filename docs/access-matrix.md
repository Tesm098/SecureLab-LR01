
# Матриця доступу ЛР №4

**Проєкт:** SecureLab, baseline 2-A «Трекер інцидентів».

**Обраний рівень:** достатній («Задовільно»).

**Головна захищена операція:** GET /api/incidents/{id}.

## 2. Політика доступу до деталей інциденту

Головною операцією лабораторної роботи №4 обрано
GET /api/incidents/{id}.

Правила доступу:

- Анонімний користувач отримує 401 Unauthorized.
- Reporter (Alice або Bob) отримує 200 OK для власного інциденту.
- Reporter отримує 404 Not Found для чужого інциденту.
- Analyst (Morgan) отримує 200 OK для перегляду інцидентів з метою аналізу.
- Administrator не отримує автоматичного права доступу до чужого ресурсу лише на підставі назви ролі.

## 3. Обґрунтування політики HTTP-відмов

Для чужого ресурсу обрано 404 Not Found.

Це дозволяє не розкривати звичайному користувачеві
факт існування інциденту іншого власника.

Відповіді для чужого та неіснуючого ресурсу повинні
мати однакові HTTP-статус, Content-Type і тіло,
за винятком службових ідентифікаторів трасування.

Ідентифікатор поточного користувача сервер отримує
лише з перевіреного HttpContext.User.

Ідентифікатор у URL визначає цільовий ресурс,
але не підтверджує право доступу до нього.

Роль Analyst дозволяє перегляд інцидентів для аналізу,
але не надає автоматичного права змінювати або
видаляти їх.

## 4. Межі реалізації

На рівні «Задовільно» реалізується контроль доступу
до GET /api/incidents/{id}.

Заплановані перевірки:

- A-02 — власник читає власний інцидент.
- A-03 — інший Reporter не читає чужий інцидент.
- A-03R — Analyst читає інцидент для аналізу.

Захист списку, update/delete, triage, internal comments,
search і severity-summary не входить до обраного рівня.

Ця матриця визначає очікуваний контракт.
Його реалізація та фактичні результати тестів
будуть зафіксовані в наступних етапах роботи.
